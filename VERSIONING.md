# Versioning Policy

This repository uses Semantic Versioning as a practical release convention.

- **MAJOR**: incompatible normative semantic changes after a stable baseline.
- **MINOR**: backward-incompatible or materially additive draft changes before v1.0; backward-compatible feature additions after v1.0.
- **PATCH**: editorial corrections, clarifications, and non-semantic fixes.

## Pre-1.0 status

All `0.x` releases are pre-standard public-review releases. Implementers should bind artifacts and conformance claims to an exact specification version.

## Requirement identifiers

Published requirement identifiers are not reused for a different meaning. A withdrawn requirement remains reserved and is marked withdrawn or superseded.

## Schema identifiers

Schemas include versioned `$id` values. Breaking schema changes require a new specification release.
